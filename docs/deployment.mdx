# Deployment

## Build

Generate an optimized production build:

```bash
npm run build
```

This creates a `dist/` directory containing:

- Minified JavaScript bundles
- Optimized CSS with purged unused styles
- Static assets (favicons, images)
- Source maps (uploaded to Faro if configured)

## Preview Production Locally

Verify the build output:

```bash
npm run preview
```

Serves the `dist/` folder at `http://localhost:4173` by default.

## Static Hosting

Satranj is a **fully client-side application with no required backend server**. It can be deployed to any static hosting provider; an optional serverless function proxies AI provider requests when available.

### Cloudflare Pages

1. Connect your GitHub repository
2. Set build command: `npm run build`
3. Set output directory: `dist`
4. Add environment variables in **Settings → Environment variables**:

| Variable | Value |
|----------|-------|
| `VITE_FARO_COLLECTOR_URL` | Your Faro collector endpoint |
| `FARO_API_KEY` | Your Grafana Cloud API key |

5. Cloudflare Pages automatically deploys the `functions/` directory as **Pages Functions**, so `/api/proxy` is available in production without extra configuration.
6. The `public/_headers` file is copied into `dist/` and applies security and CORS headers on hosts that honor it.

### Vercel

1. Import project from GitHub
2. Framework preset: **Vite**
3. Build command: `npm run build`
4. Output directory: `dist`
5. Add environment variables in project settings

### Netlify

1. Connect to GitHub repository
2. Build command: `npm run build`
3. Publish directory: `dist`
4. Add environment variables in **Site settings → Environment variables**

### Self-Hosted / Nginx

Copy the `dist/` contents to your web server:

```bash
scp -r dist/* user@server:/var/www/satranj/
```

Example Nginx configuration:

```nginx
server {
    listen 80;
    server_name satranj.example.com;
    root /var/www/satranj;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

## Serverless AI Proxy (Cloudflare Pages Function)

The AI Coach sends provider requests through the same-origin `/api/proxy` endpoint. In production this is served by a **Cloudflare Pages Function** at `functions/api/proxy.js`:

- Handles `OPTIONS` preflight with `Access-Control-Allow-*` headers.
- Validates the `targetUrl` against the same host allow-list as the dev middleware and rejects anything else with `403`.
- Forwards `Content-Type`, `Authorization`, `HTTP-Referer`, and `X-Title` headers, with a 25-second upstream timeout, then streams the response back.

```javascript
// functions/api/proxy.js
export async function onRequestPost(context) {
  const { targetUrl, body, headers, method } = await context.request.json();
  if (!isAllowedTarget(targetUrl)) {
    return new Response(JSON.stringify({ error: 'Blocked host' }), { status: 403 });
  }
  // ...forward to the provider...
}
```

> **Note:** On hosts other than Cloudflare Pages the function is absent. The providers detect the missing endpoint and fall back to a direct `fetch` to the vendor, which then depends on the vendor's CORS policy and the app's CSP `connect-src`.

## Environment Variables at Build Time

Since Vite is a **build-time environment** system, variables prefixed with `VITE_` are embedded into the client bundle during the build process. To change them:

1. Update the environment variable in your hosting platform
2. **Trigger a new build and deploy** (not just a redeploy)

## Source Map Uploads

The `@grafana/faro-rollup-plugin` automatically uploads source maps during the build, enabling readable stack traces in Grafana Cloud:

```javascript
faroUploader({
  appName: 'satranj.amritai.org',
  endpoint: 'https://faro-api-prod-ap-south-1.grafana.net/faro/api/v1',
  appId: '1960',
  stackId: '1619876',
  verbose: true,
  apiKey: process.env.FARO_API_KEY,
  gzipContents: true,
})
```

> **Note:** Source maps are excluded from the `dist/` folder after upload. Remove the plugin from `vite.config.js` if you don't need this feature.
